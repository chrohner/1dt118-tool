Guide to the Attack Graph Lab

The Attack Graph Lab is a browser tool for the attack graphs of module M1a. You open or import a flow of facts and actions, state your assumptions, execute successful actions, find the cheapest route to a goal and compare controls. Everything runs in your browser: no installation, no account, and your files stay on your device.

This page is the reference. The slide deck Using the Attack Graph Lab walks through the same steps with screenshots.

1. Getting started

  1. Open chrohner.github.io/1dt118-tool/attack-flow-companion/ in a current Chrome, Edge or Firefox. Do not open a downloaded copy with file://; the tool needs a web address.
  2. Click Portal example to load the university portal model from the lecture. Clicking it again resets the example.
  3. Click Save project whenever you want to keep your work. The browser's memory is not a backup.

The Guide button in the top bar opens this page.

3. A first tour: the portal example

  1. Portal example, then 1 · Setup: the goal is X's records read; read the initial facts and the action efforts (reset 1 h, phishing 3 h, login 1 h, read 0 h, injection 6 h).
  2. 2 · Execute: select login. It is blocked; Required inputs shows that credential held is missing. Execute reset, then login and read; the goal holds.
  3. 3 · Analyse → Find minimum effort: 2 h through reset, login, read.
  4. Course intervention: choose verification, mfa and mfa patch in turn; each becomes a new scenario.
  5. Analyse scenarios: 2 h, 4 h (phishing), 6 h (injection), goal unreachable.
  6. Save project, then reopen the file with Open JSON / project.

4. Import your own flow

  1. Draw the flow in the online Attack Flow Builder. Facts are conditions, actions are actions, and joins are AND/OR operators.
  2. In the Builder, use File → Export STIX File (the documentation may call it Publish Attack Flow). This gives a .json file. Also keep the Builder's own .afb file: you need it to edit the drawing later, and the Lab cannot open it.
  3. In the Lab, click Open JSON / project and choose the .json file.
  4. Read the import line above the graph:
    ✓ Import profile checkedThe flow can be executed and analysed.
    ⚠ incoming-edge choice(s) required in SetupSome node has several inputs without an AND/OR operator. Choose AND or OR in Interpret incoming edges.
    ⚠ blocking compatibility issue(s) — preview onlyThe flow uses something the Lab does not support, such as failure branches. You can look at it but not execute it; change the flow in the Builder.

An import starts with automatic assumptions so that you can explore at once: starting conditions are true, actions without inputs may start, joins without an operator are OR, the goal is the node farthest downstream, and every missing effort is 1 hour. These are placeholders. Check them in Setup before you draw any conclusion.

To change the drawing itself, edit the .afb file in the Builder and import a new export. A new import does not copy efforts across by name, so save your project first.

5. Check the setup

Everything in 1 · Setup belongs to the current scenario.

FieldWhat to check
GoalThe fact (or completed action) the attacker wants.
Interpret incoming edgesOnly when some node has several unlabelled inputs: AND if all are needed, OR if any one suffices.
Facts true initiallyTicked facts hold from the start. An unticked fact is not established: that is your assumption, not a proof.
Entry actions with no prerequisitesOnly when the flow has actions without inputs: tick those the attacker may start with. They still cost effort.
Scenario assumptionsWrite down what this scenario assumes.
Action effortAvailable: untick to take an action out of this scenario. The effort column: reference-adversary hours (or the example's own unit), not elapsed time and not probabilities. Record where a number comes from in Effort basis / evidence (in 2 · Execute, below the selected action).

Changing any of these resets the execution and clears results for that scenario.

6. Execute actions yourself

  1. Open 2 · Execute. Under Explore an action, each action is marked enabled, blocked, off or ✓ done. You can also click a node in the graph.
  2. The inspector shows Required inputs, each marked as holding or missing, and Direct effects on success.
  3. Click Execute … successfully to apply an enabled action. Every action succeeds by assumption and runs at most once; facts stay true.
  4. Execution history lists what each step established and the cumulative effort. Use Undo or Reset.

7. Find the cheapest route

  1. In 3 · Analyse, write Your prediction (optional) first.
  2. Check reachability answers yes or no. Find minimum effort searches for the cheapest route, from the initial facts (not from your manual execution).
  3. The result gives the minimum and a witness: one cheapest sequence of successful actions with cumulative effort. Shared work is charged once.
  4. Replay witness on graph applies the witness in 2 · Execute, so you can inspect each step.

8. Model a control and compare

  1. Type a name in Name a comparison…, for example "patch web server", and click Duplicate current. The new scenario is selected; the original stays unchanged.
  2. In 1 · Setup, change one thing that represents the control:
    • untick a fact in Facts true initially when the control removes a condition (patching makes "vulnerability present" false);
    • untick Available when the control removes an action altogether;
    • raise an effort when the control makes an action harder but still possible.
  3. Note the change in Scenario assumptions.
  4. Under Compare your scenarios, click Analyse scenarios. The table lists each scenario's changes, result and witness.

Change one assumption per scenario, so that a difference in the result has one cause. For the portal, Course intervention creates prepared controls from the first scenario.

9. State graph and replay

State graph

Click State graph above the drawing. Each box is a state, the set of facts held (I = initial facts); each arrow is a successful action. Your executed steps are numbered; gold boxes are goal states; faded boxes can no longer reach the goal.

  • Blocked transitions. By default the graph is drawn with all inputs available, and transitions that the current scenario blocks are dashed and marked ✗. Boxes that this scenario cannot reach are dashed. A red line lists what the scenario withholds.
  • View options (folded): Stop at the first goal state, Only states that can still reach the goal, and Draw blocked transitions (dashed) against all inputs, a named scenario, or nothing.
  • Above 80 states the view shows counts per layer instead of a drawing.

Replay

Once you have executed actions or found a minimum, the Replay bar appears above the graph. Choose the current execution or the effort witness, then ▶ Play; the step buttons move one action at a time and Speed sets the pace. Replay only animates: it does not change your execution or results. With reduced motion set in your operating system, use the step buttons.

10. Optional analyses (Advanced)

These are hidden until you switch them on under Advanced ▾. Each has its own stated rules, and the setting is saved with your project.

OptionWhere it appearsQuestion it answers
Path counting3 · Analyse: choose a Convention, then CountHow many attack paths are there, and how long are they? Graph paths, executable sequences and minimal attacks give different counts: choose the convention before you count.
Mean effort to failure3 · Analyse: Compute METFExpected effort for an attacker who does not know the graph and tries every available action at once. Efforts are read as means of random efforts. It is never above the minimum effort, which assumes an attacker who knows the whole graph.
Show search effortUnder the minimum-effort resultHow many states the exact search explored (not the size of the state graph).
Probability tab4 · Probability: enter values, then Compute probabilityProbability that the goal is reached when each action succeeds independently with the probability you enter. Never combined with effort.

11. Save, reopen and export

  • Save project downloads one .json file with the imported flow, all scenarios and assumptions, and a description of the analysis rules. Reopen it with Open JSON / project; results are recomputed, not trusted from the file.
  • Export report downloads a readable Markdown summary: assumptions, efforts, results, witnesses, the analysis rules and the readings behind the conventions used.
  • If you replaced a project by mistake, Restore previous project (shown after an import) brings back the one before. Do not rely on it: save first.

12. Reading the results

ResultMeaning
EXACT MINIMUMNo cheaper route exists under the current assumptions. The witness is one cheapest route; others may tie.
Goal unreachableNo sequence of available actions reaches the goal under the current assumptions. This says nothing about routes the model leaves out.
Search incompleteA limit stopped the search. It is neither a minimum nor a proof of unreachability.
preview onlyThe import uses unsupported constructs; see section 4.

Every result is conditional on the model: facts persist, actions succeed and run once, efforts add. The tool makes no claim about real-world security.

13. Limits and troubleshooting

SizeFlows up to 2 MiB, 500 STIX objects and 200 executable nodes. The search stops at 50,000 states or 5 seconds and then says incomplete.
Not supportedFailure branches, negation (a fact becoming false), retries, and the Builder's .afb files.
A button is greyed outThe setup is incomplete: check the goal, the incoming-edge choices and missing efforts in 1 · Setup.
An action stays blockedSelect it in 2 · Execute; Required inputs names what is missing. It may also be unticked under Available.
The state graph shows a tableMore than 80 states: the view counts states instead of drawing them.
Lost workSave often. Reloading the page or importing another file replaces the current project.
